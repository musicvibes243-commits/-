# Как передавать исходники

Рабочих канала два. Оба проверены на деле.

## 1. Вложение в чат — для одного-двух файлов

Прошло восемь файлов, включая четыре видео за одно сообщение. Ничего
настраивать не надо.

## 2. Загрузка в эту папку на GitHub — для пачек

Тоже работает: проверено загрузкой двух видео по 12 МБ.

**Только через браузер.** Приложение GitHub загружать файлы не умеет вообще
— в нём такой кнопки нет, искать бесполезно.

Порядок:

1. Открыть в браузере (не в приложении):
   `github.com/musicvibes243-commits/-/upload/claude/shorts-clips-instagram-tiktok-onyx2t/input`
2. Нажать синюю надпись **«choose your files»** в середине рамки.
   «Drag files here» на телефоне не работает — перетаскивать нечем.
3. Выбрать видео. Можно сразу несколько.
4. **Дождаться, пока под рамкой появятся имена файлов и полоска дойдёт до
   конца.** Если нажать коммит раньше — вылезет «Add some files to include
   in this commit», это значит «файл ещё не приложен».
5. Внизу **«Commit changes»**.
6. Написать мне, что загрузил: сам я в папку не заглядываю, уведомлений нет.

Файлообменники (Google Drive, Яндекс.Диск, Dropbox) не подойдут — они
закрыты сетевой политикой с моей стороны, по ссылке я ничего не скачаю.

## Лимит и как в него уложиться

**25 МБ на файл** — одинаково для обоих каналов.

Дело не в длине ролика, а в битрейте:

| Откуда | Битрейт | Сколько влезает в 25 МБ |
|---|---|---|
| обычный экспорт с телефона / CapCut | ~3 Мбит/с | **около 60 секунд** |
| экспорт «максимальное качество» из приложения 360-камеры | ~29 Мбит/с | **около 7 секунд** |

Разница в десять раз при одном и том же лимите.

### Порядок в CapCut

1. Новый проект → выбрать видео
2. Обрезать до 30–60 секунд
3. «Экспорт» вверху справа
4. Поставить **1080P**, **30 кадров**, **«Скорость кода» → Рекомендуется**
5. CapCut показывает примерный размер прямо на этом экране — смотреть,
   чтобы было меньше 25 МБ
6. Сохранится в галерею, оттуда в чат или на GitHub

Не влезает — резать на два куска.

## Чего делать не надо

- Не слать сырьё камеры (`.insv`, `.insp`) — не принимает ни один канал.
  Только MP4 или MOV после экспорта.
- Не грузить в 4K и 5.7K. Апскейл и резкость вытягиваются при монтаже, как
  вытянулись из 720p в первых роликах.
- Не слать исходник целиком: из девяти минут в монтаж попадёт секунд
  двадцать.

## Можно ли прислать 360 и чтобы кадрировал я

Технически да: `v360` разворачивает сферу в плоский кадр, а через `sendcmd`
обзор можно вести — плавная панорама, облёт, разворот с ямы на результат.
Проверено, работает.

Упирается в разрешение. В кадр 1080×1920 при обзоре 70° уходит меньше пятой
части ширины сферы:

| Разрешение сферы | Пикселей в кадр | Растяжение |
|---|---|---|
| 5.7K (5760×2880) | 1120 | 0.96× — впору |
| 4K (3840×1920) | 747 | 1.45× — мягко |
| 2.9K (2880×1440) | 560 | 1.93× — мыло |

Сфера должна приехать в 5.7K, а 5.7K в 25 МБ за 20 секунд — это уже сильное
сжатие само по себе. Две потери складываются.

**Поэтому по умолчанию лучше так:** кадрируешь в приложении камеры, оно
работает с полным исходником. Присылаешь плоский 9:16. Рез, цвет,
стабилизация, тексты, снятие вотермарка — на мне.

**Слать 360 стоит,** когда нужен ход камеры, которого в приложении не
сделать. Тогда куски по 5–10 секунд, максимальное доступное разрешение,
и мягкость картинки как плата за свободу кадра.

## Субтитры

Если есть расшифровка речи — положить рядом `.srt` с тем же именем.
Автосубтитры из CapCut подойдут, термины поправлю сам.
